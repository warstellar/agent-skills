# Handoff outline

Write the finished external document in English, using sentence case. Fill this outline with project facts; do not produce a long brand book by default or leave empty sections. Keep internal strategic notes separate from customer-facing material.

## Decision and status

Record the name, descriptor, visual direction, and status: user-selected, recommended, or draft. Include the date, decision source, and a link to the inspected variant. Explain the reason and principal tradeoff. Choosing a name does not approve every proposed detail.

## Product and audience

Describe the audience, concrete job, primary scenario, promise, and limits. Distinguish verified product capabilities from statements supplied only in the brief.

## Verbal identity

Provide positioning, descriptor, hero heading, support copy, and CTA. Give short voice rules with a concrete example. Mark copy awaiting approval. Do not promise improvement in every comparison when unchanged or worse results are possible.

## Visual system

Explain the idea, composition, typography, color roles, imagery, mark, and behavior in product UI and at small sizes. Attach references and actual previews. Label font choices and color values as final only after selection and verification; track licensing separately. A generated logo image is not a production vector master.

## Applications and files

List demonstrated surfaces, artifact locations, exact prompts and metadata, reusable material, and missing source files. Separate completed artifacts from the next commission: mark/wordmark, icon, mini brand sheet, hero, social/launch assets, forms, or results, as the project requires. This is not a mandatory asset list for every handoff.

## Guardrails and open decisions

Give practical do/don't guidance for the selected direction. List unresolved questions, name/domain/legal checks, licensing, missing UI states, and source limitations. End with one clear next action for the recipient.
